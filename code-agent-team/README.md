# 코드 에이전트 팀

토큰을 적게 쓰면서 코드 품질을 지키기 위한 AI 에이전트 구성안입니다.
`code-agent-team.html`을 브라우저로 열면 구성, 요청별 경로, 탐색 기준, 호출 수 비교, 검수 양식을 볼 수 있습니다.

## 핵심

- 기획·프론트엔드·백엔드·검수를 각각 다른 에이전트로 나누지 않고, **메인 에이전트 하나가 한 맥락에서 코드를 짭니다**.
- 검수는 작성 과정을 모르는 **검수 에이전트가 diff만 보고** 합니다.
- 서브에이전트는 부를 때마다 맥락 없이 새로 시작해서 같은 파일을 다시 읽습니다. 그래서 **호출 수를 줄이는 것이 토큰을 줄이는 방법**입니다.

## 구성

| 역할 | 하는 일 | 호출 시점 |
|---|---|---|
| 메인 | 요구사항 정리 → 설계 → 프론트·백엔드 구현 → 테스트 → 최종 보고. 파일 수정과 실행 권한 전부 | 항상 |
| 탐색 에이전트 (읽기 전용) | 관련 파일과 흐름을 찾아 `파일:줄` 목록과 요약만 반환 | 큰 저장소일 때만 |
| 검수 에이전트 (읽기 전용) | 버그, 보안, 요구사항 누락, 테스트 빈틈 지적 | 구현 후 1번 (큰 작업은 설계 후 1번 더) |

## 원리

1. **맥락은 이어 간다**: API 계약을 프론트와 백엔드가 같이 알아야 하므로 한 맥락에서 작업합니다.
2. **남이 검토한다**: 작성자가 자기 코드를 검토하지 않습니다.
3. **요구사항으로 이어진다**: 요구사항에 R1, R2 번호를 붙이고 코드와 테스트를 연결합니다. 확인 수준은 `[확인]`(테스트·실행), `[추론]`(코드만 읽음), `[미확인]`으로 표시합니다.
4. **필요할 때만 부른다**: 요청 크기에 따라 경로가 달라집니다.

## 요청별 경로

| 요청 | 경로 | 서브에이전트 호출 |
|---|---|---|
| 작은 수정 (오타, 파일 한두 개) | 메인이 바로 수정 | 0회 |
| 기능 하나 | 구현 → 테스트 → 검수 → 반영 | 1회 |
| 큰 작업 | 사용자 승인 → 탐색 → 설계 → 검수 → 구현·테스트 → 검수 | 3회 |

## 탐색 에이전트를 부르는 기준

저장소 크기보다 **관련 코드를 찾으려면 나중에 필요 없는 파일까지 많이 읽어야 하는가**가 기준입니다.

- 필요 없음: 파일 수십 개인 프로젝트, 구조가 뻔한 프로젝트, 위치가 정해진 요청
- 필요함: 모노레포, 흐름을 따라가야 하는 질문, 처음 보는 레거시 코드, 호출처가 흩어진 변경
- 간단한 기준: 검색 2~3번으로 위치가 안 나오면 부릅니다.

## 토큰 절약 장치

- 검토는 되돌리기 비싼 곳에서만 합니다.
- 탐색과 검수는 더 가벼운 모델로 돌립니다.
- 검수자에게는 요구사항, diff, 테스트 결과만 넘깁니다.
- 재검수는 고친 부분만 봅니다.
- 테스트 로그는 실패한 부분만 넘깁니다.
- 돌려받는 답은 변경 파일, 핵심 결정 3줄, 미해결 사항만 받습니다.
- 작업이 끝나면 `learnings.md`에 한 줄을 남기고 다음 작업 설계 때 먼저 읽습니다.

> 페이지의 호출 수 비교는 서브에이전트 호출 수만 센 개념 비교이며, 실측 토큰 값이 아닙니다.
