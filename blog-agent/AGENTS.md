# 블로그 에이전트 운영

이 프로젝트는 유라클의 기사·공식 자료를 근거로 한국어 블로그 글을 작성하고, 사용자가 요청하면 새 Sites 블로그에 게시한다. 최신 대화 지시가 우선한다.

- 편집에는 `.agents/skills/uracle-blog/SKILL.md`와 연결한 승인 샘플을 적용한다.
- 사이트는 `sites/uracle-blog/`다. `README.md`와 `.openai/hosting.json`을 먼저 읽고 같은 Site를 갱신한다. 사이트를 중복 생성하지 않는다.
- 사용자가 사이트용 작성·게시를 요청하면 조사·작성·검증·배포 확인까지 수행한다. 사용자가 “초안만” 또는 “게시하지 마”라고 하면 해당 범위를 지킨다. 불필요한 매 단계 재승인을 요구하지 않는다.
- **“글 게시”**는 이 프로젝트에서 만든 Sites 블로그에 글을 실제로 올리라는 실행 명령이다. 가장 최근 대화의 완성된 미게시 초안을 우선 사용하고, 없으면 `drafts/`의 최신 미게시 초안을 선택한다. 주제나 초안을 함께 지정하면 그 지시가 우선한다. 한 번의 “글 게시”에는 기본 한 편을 게시하며, 여러 편을 지정한 경우 그 범위대로 게시한다.
- “글 게시”를 실행할 때 원문 확인 → 중복 확인 → 강조·요약·출처 반영 → 테스트·빌드 → 같은 Site에 배포 → 성공 확인과 글 URL 반환까지 수행한다. 초안 경로·사건 식별자·게시 URL은 `sites/uracle-blog/content/publications.json`에 기록해 반복 명령으로 같은 초안을 다시 올리지 않는다. 미게시 초안이 없으면 이를 알리고 새 글을 임의로 중복 생성하지 않는다.
- 현재 운영 방식은 요청형이다. 정기 예약은 사용자가 다시 요청할 때만 설정한다.
- 원고와 중복 기록은 `sites/uracle-blog/content/posts.json`에 있다. 원문 전체와 기존 사건을 확인하고 source별 시점을 기록한다.
- 썸네일은 글별로 구별되는 사진 배경에 검은색 반투명 레이어를 덮고, 그 위에 흰색 큰 글자를 중앙에 2~3줄 배치한다. 색상·컬러 틴트를 넣지 않고 흑백으로 제작한다. 홈페이지 회사 사진을 모든 글의 썸네일로 재사용하지 않는다. `thumbnail` 메타데이터와 기존 제작 기록은 사이트 README를 참고한다.
- 기존 검토용 원고를 확인 없이 일괄 게시하지 않는다. 내부 조사 메모나 비공개 Drive 파일 전체를 사이트에 노출하지 않는다.
- 배포 전 관련 테스트·빌드를 실행하고 Sites 스킬의 소스·archive·배포 절차를 따른다. 기존 접근 범위를 보존한다.
- 자격 증명을 소스·문서·출력에 보관하지 않는다. 실제 배포 성공을 확인한 경우에만 게시 완료라고 말한다.

## 채팅 명령: 커밋

사용자가 이 블로그 에이전트 프로젝트에서 **“커밋”**이라고 요청하면, 마지막 GitHub 반영 이후의 프로젝트 변경과 진행 내용을 확인하고 Conventional Commits 형식의 제목과 설명 본문을 갖춘 커밋을 만들어 GitHub에 반영한다. 별도의 반복 승인을 요구하지 않는다. 사용자가 초안·로컬 커밋 등 범위를 따로 지정하면 그 지시를 따른다.

- 대상 로컬 루트: `C:/Users/USER/Documents/ChatGPT/블로그 에이전트`.
- 대상 저장소: `ShinHyerin/daejeon_01`, 기본 브랜치: `main`, 허용 경로: `blog-agent/` 아래만.
- 이 명령의 권한을 다른 프로젝트·저장소·저장소 루트 파일에 적용하지 않는다. 변경 목록과 커밋 diff가 모두 `blog-agent/` 아래인지 확인한다.
- 실제 변경에 맞게 `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore` 등을 고르고 `type(scope): description`을 사용한다. 본문에는 무엇을 왜 바꿨는지, 확인한 테스트·빌드와 한계를 적는다. 서로 독립적인 변경은 필요하면 커밋을 나눈다.
- 프로젝트의 소스·필요한 이미지·운영 지침·진행 문서를 포함한다. 중첩된 Sites 저장소는 Git 메타데이터 대신 일반 소스 파일로 기록한다. 비밀값·로그·실행 캐시·빌드 결과·배포 압축 파일은 제외한다.
- 관련 테스트·빌드를 실행하고 기존 원격 변경을 보존한다. 원격이 앞서 있으면 최신 내용을 확인해 조정한다. 강제 덮어쓰기는 하지 않는다.
- GitHub 연결 도구로 커밋·브랜치 반영을 완료할 수 있으면 로컬 루트가 Git 저장소가 아니어도 그 도구를 사용한다. 내용과 최종 브랜치 상태를 다시 읽고 커밋 링크를 반환한다.
- 변경이 없으면 빈 커밋을 만들지 않고 그 사실을 알린다. “커밋”만으로 Sites 재배포·글 추가 게시·접근 범위 변경·예약 생성을 실행하지 않는다.
