# 유라클 블로그 편집

유라클의 제품과 회사 소식을 꾸준히 기록하는 한국어 블로그용 스킬이다. 기본은 기사 본문에 근거한 문단형 게시물이며, 핵심 문장 강조와 맨 아래 짧은 요약을 붙인다. 제품 설명이 필요하면 근거 범위에서 쉽게 풀어 쓴다. 과장된 홍보나 구매·문의 유도 문구를 임의로 추가하지 않는다.

## 시작 자료

- 처음 작성하거나 형식을 맞출 때 [승인한 샘플](references/approved-sample.md)을 읽는다. 문체·구성의 예시이며 다른 기사의 사실 근거로 쓰지 않는다.
- 기존 수집 자료가 필요하면 [자료 위치](references/sources.md)를 읽는다. 저장 요약은 탐색용이며 원문 확인을 대신하지 않는다.
- 기존 블로그 문체를 참고할 때는 자료 위치에 연결한 Drive의 ‘유라클 블로그 표본 8편’ 문서를 읽어 같은 유형의 표본을 고른 뒤 해당 원문을 확인한다.
- 글 작성 전 [유라클 기존 블로그](https://uracle.blog/)에서 작성할 주제·유형과 관련된 글의 본문을 읽고, 회사가 사용하는 용어·문체·설명 방식·문단 구성을 우선 참고한다. 사용자가 요청한 '기존 글 학습'은 이 참고 과정을 뜻한다. 목록과 제목만 보고 글을 읽었다고 하지 않는다. 실제 읽은 글의 URL과 참고한 특징은 게시물 밖의 짧은 검토 메모로 남긴다. 접속이나 본문 확인에 실패하면 알리고 승인 샘플로 보완한다.
- 기획 대화만 요청하면 대화만 한다. 현재 요청에서 허용한 작성·저장 범위에 맞춰 작업한다.

## 호출과 기본 작업

사용자가 **“유라클 블로그 초안”** 또는 같은 뜻으로 작성해 달라고 하면 이 스킬을 적용한다. 호출 문구를 인용해 규칙을 고치거나 설명해 달라는 요청은 설정·설명 작업으로 처리한다.

기본 실행 순서는 **기사 확인 → 중복 검사 → 유라클 기존 블로그의 관련 글 참고 → 본문 작성 → 강조 문장 지정 → 하단 요약·출처 작성 → 문체 교정 → 사실 재대조**이다.

- 기사 링크나 주제가 주어지면 그것부터 검토한다. 지정하지 않으면 기존 수집 자료에서 후보를 찾고 필요시 웹검색으로 보완해, 본문을 확인할 수 있고 핵심 관련성이 있는 한 사건의 초안을 만든다. 적합한 자료가 없으면 그 사유를 알린다.
- 작성 시 [외부 참고와 한국어 편집 기준](references/editorial-references.md)을 읽고 이 프로젝트에 채택한 부분만 적용한다. 외부 저장소 설치를 전제로 하지 않는다.
- 새 지침이나 예시가 필요하면 GitHub 자료를 웹검색하고 실제 파일을 읽은 뒤 적합성을 판단한다. 검색 결과 제목만 보고 채택하지 않는다. 매번 같은 자료를 다시 검색하거나 새로운 스킬을 설치할 필요는 없다.
- GitHub는 문체·작업 방식 참고 자료다. 게시물의 회사 사실은 기사·공식 자료에서 확인한다. 추가로 참고한 GitHub 링크와 적용 범위를 사용자에게 알리고, 글의 기사 출처와 분리해 표시한다. 확인하지 못한 자료를 참고했다고 말하지 않는다.

## 한국어 문체 교정

유라클 블로그의 실제 글을 문체·용어의 우선 참고 자료로 삼는다. 승인한 샘플의 형광펜 강조·하단 요약·출처 구성은 유지한다. 과거 글의 제품 구성·수치·기술 설명은 작성 시점의 기사나 공식 자료로 다시 확인하고, 기존 글 전체를 복제하거나 과거 사실을 현재 사실처럼 옮기지 않는다. GitHub 편집 지침은 이 기준을 보완하는 데 사용한다.

초안 작성 후 승인 샘플의 차분한 존댓말을 유지하며 어색한 번역투, 이중 피동, 같은 내용의 반복, 근거 없는 의의 부풀리기와 상투적인 기대 문장을 다듬는다. 이미 자연스러운 문장은 유지한다.

교정 전후의 숫자·날짜·제품명·인용·주체·가능성·진행 상태를 대조한다. 문장을 짧게 하면서 ‘목표’를 ‘달성’으로, ‘진행 중’을 ‘완료’로 바꾸지 않는다. 기사 시점과 회사 발표라는 귀속도 유지한다. 불필요한 강조를 줄이는 일반 문체 규칙으로 사용자가 요청한 형광펜 대상과 하단 요약을 삭제하지 않는다.

마케팅 자료는 필요할 때 명료성·문체 일관성·근거 확인에 한정해 참고한다. 전환율·판매 유도·감정 자극·수치 보강·CTA 삽입을 이 블로그의 기본 목표로 삼지 않는다.

## 기사 선정과 사실 확인

1. 작성에 사용할 기사 전체 본문을 읽고 제목·매체·작성자(확인되는 경우)·발행일·원문 URL을 확인한다. 검색 요약이나 제목만으로 완성된 게시물을 만들지 않는다. 본문 확보에 실패하면 해당 기사를 보류하고 확인하지 못했다고 알린다.
2. 본문의 중심이 유라클의 제품·고객 수주·사업·협력·행사인지 판단한다. 제품명·회사 역할·고객·활동이 구체적이어야 한다. 단순 명단, 주변 사례, 시세 페이지는 제외한다. 회사명 출현 횟수가 아니라 본문의 중심성으로 판단한다.
3. 같은 발표를 다룬 기사는 하나의 사건으로 묶는다. 이전 작성·저장 목록에 접근할 수 있으면 확인한다. 목록을 확인하지 못했다면 중복 여부를 모두 확인했다고 말하지 않는다.
4. 사용할 사실을 근거와 대조한다. 제품명·고객명·날짜·수치·행위 주체·진행 상태를 원문과 맞춘다. 여러 기사를 합치면 근거를 구별한다.
5. 회사 발표는 “회사에 따르면”, “밝혔다”처럼 주체를 표시한다. MOU, 수주, 개발 중, 목표, 완료를 구별한다. 내부 실증을 모든 고객의 효과로 일반화하거나 특정 제품 매출을 전체 회사 매출로 확대하지 않는다.
6. 근거 없는 계약 금액·고객 평가·시장 순위·성능·인용문·미래 성과를 추가하지 않는다. 과거 기사 내용은 보도 시점 기준으로 표현한다. 현재 상태라고 쓸 때는 별도로 확인한다.

## 게시물 구성

아래 순서로 작성한다. 원문의 사실을 유지하면서 문장을 재구성한다. 기사 전문 복제를 기본으로 삼지 않으며 인용 시 적용되는 인용·저작권 제한을 지킨다.

1. **제목:** 회사와 사건이 드러나는 사실 중심 제목.
2. **본문:** 승인한 샘플처럼 짧은 문단으로 구성한다. 기사에 따라 길이를 조절한다. 추가 설명의 사실도 출처를 확인한다.
3. **본문 안의 강조:** 사건·제품 역할·협력의 핵심을 보여주는 문장 통상 2~3곳. 근거가 부족하면 개수를 채우지 않는다. 요약에만 강조를 몰아넣지 않는다.
4. **맨 아래 핵심 요약:** 본문 뒤 2~3줄 또는 항목 3개 이내. 본문에 없던 결론을 추가하지 않는다.
5. **출처:** 매체명·발행일·실제 원문 링크. 확인한 작성자가 있으면 함께 적는다. 추측해서 채우지 않는다.

문체는 차분한 한국어 존댓말이다. 채팅 초안에서는 강조 대상을 굵게 표시하고 형광펜 적용 대상이라고 설명한다. HTML 요청 시에는 해당 문장에 형광펜 스타일을 적용할 수 있다. 네이버 편집기에 실제 서식이 적용됐는지는 확인한 경우에만 말한다.

## 검토와 작업 범위

- 내보내기 전에 본문·요약의 모든 사실·수치·진행 상태, 강조 문장과 출처를 원문과 다시 대조한다. 미확인 문장은 제거하거나 보류한다. 사실 오류가 절대 발생하지 않는다고 보장하지 않는다.
- 완성 글과 내부 검토 메모를 분리한다. 확인 실패 시 완성된 사실 기반 글처럼 제시하지 않는다.
- 기본 산출물은 검토용 초안이다. 요청한 경우 파일이나 Drive에 저장한다. 스킬 사용 자체는 네이버 게시·계정 생성·예약 실행·사이트 배포를 허용하지 않는다. 해당 작업의 명시적 지시와 실제 연결·성공 확인이 필요하다. 이미 받은 유효한 지시는 존중한다.
