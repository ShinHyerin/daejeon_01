# 유라클 블로그 홈페이지와 요청형 게시 에이전트

상태: 사용자 승인 후 2026년 11월 3일 제작·첫 글 게시 완료. 배포 결과는 `docs/2026-11-03-site-progress.md`에 기록했다.

## 목적과 운영 방식

유라클 기사와 공식 홈페이지 정보를 한국어 글로 정리해 누적하는 독립 블로그를 만든다. 사용자가 채팅에서 작성·게시를 요청하면 에이전트가 조사, 작성, 검토, 사이트 반영, 배포 확인까지 수행한다. 사용자가 편집기에 글을 붙여 넣는 단계는 없다.

사용자는 처음 정기 운영을 요청했으나 이후 “일단은 내가 말하면 작성하는 걸로 변경”, “나중에 주기적으로”라고 수정했다. 현재는 자동 예약을 만들지 않는다. 이미 만든 글의 수정·추가 게시에도 같은 사이트를 사용한다.

## 확인한 자료

- 디자인과 회사 정보: https://uracle.co.kr/
- 로고와 공식 색상: https://uracle.co.kr/company/ci
- 상단 사진 후보: https://uracle.co.kr/company/company 에 표시된 회사 사진. 페이지가 참조하는 `/company/office.png`가 후보이며 실제 로딩과 화면 적합성은 구현 시 확인한다.
- 소식 후보: https://uracle.co.kr/pr-ir/pr
- 문체: 프로젝트의 `uracle-blog` 스킬, 승인한 KT 협력 샘플, 작성 시점에 읽은 https://uracle.blog/ 의 관련 게시물.

Drive에서 기존 유라클 조사 문서에 접근 가능한 것을 확인했다. 반면 현재 Sites의 플러그인 적격성 결과에서 Google Drive의 사이트 내부 연결은 denied다. 따라서 현재 사이트에는 Drive 연결을 선언하지 않는다. 에이전트는 이 대화의 허용된 Drive 도구로 필요한 자료를 참고할 수 있으며, 회사 사실은 웹 원문으로 재확인한다. 내부 검토 메모와 조사 문서 전체를 사이트에 노출하지 않는다.

## 화면 구성

사용자가 지정한 흰 배경과 검은 글자를 기본으로 한다. 강조색은 공식 CI의 Uracle Red `#E30613`, 본문은 Ink Black `#1D1D1B`, 보조 영역은 옅은 회색으로 한다. 공식 홈페이지의 여백과 선명한 제목, 절제된 빨간 강조를 참고하되 블로그의 읽기와 탐색을 우선한다.

홈페이지의 순서는 다음과 같다.

1. 흰색 머리말: 공식 비율을 유지한 유라클 로고, 블로그 이름, 글 목록과 회사 홈페이지 링크.
2. 대표 영역: “유라클 블로그”라는 큰 검은 제목과 빨간 포인트, 공식 회사 사진. 사진 위에 긴 문장을 얹지 않고 흰 영역의 제목과 함께 배치한다. 모바일에서는 제목 아래에 사진을 배치한다.
3. 글 탐색: 전체, 회사 소식, AI, 모바일 플랫폼 분류와 제목·요약 기반 검색.
4. 최신 글: 제목, 짧은 요약, 분류, 실제 게시일을 보여 주는 목록. 대표 글에는 넓은 영역을 사용하고 나머지는 읽기 쉬운 카드 또는 행으로 배치한다.
5. 바닥말: 유라클 공식 홈페이지 링크, 사이트의 편집 방식과 자료 출처에 관한 짧은 안내. 별도 확인 없이 “공식 운영 블로그” 또는 회사가 직접 발행한 글이라고 주장하지 않는다.

개별 글은 제목, 분류, 실제 게시일, 본문, 핵심 강조 문장, 맨 아래 핵심 요약, 원문 링크 순서로 보여 준다. 기사 원문 발행일과 블로그 게시일을 구별한다. 빨간 글자는 짧은 표제·분류·핵심 구절에 사용하고 본문 전체를 빨갛게 만들지 않는다. 기존 스킬의 핵심 문장 강조는 옅은 빨간 배경과 진한 글자로 구현할 수 있다.

## 구현 방식과 대안

현재 운영에는 에이전트가 콘텐츠 파일을 갱신하고 Sites에 배포하는 방식이 가장 단순하다. 데이터베이스와 별도 사용자용 글쓰기 화면 없이도 요청형 작성·게시를 모두 처리할 수 있다. 사이트는 글별 주소를 가진 정적 HTML로 만들고, 원고와 목록은 프로젝트 안의 구조화된 콘텐츠 파일에 보관한다. 이는 구현자의 제안이며 사용자가 프로그래밍 방식을 지정한 것은 아니다.

대안은 데이터베이스와 에이전트용 게시 도구를 처음부터 만드는 방식이다. 정기 작업이 재배포 없이 새 글을 저장하기에는 적합하지만, 현재 요청형 운영에는 인증과 저장소 설정을 추가한다. 정기 운영을 다시 요청하면 이 경로를 검토하고 실제 무인 작성·쓰기·읽기 검증 후 예약한다. 지금의 결과를 무인 발행이 검증된 시스템이라고 설명하지 않는다.

네이버나 기존 `uracle.blog`에 글을 올리는 것은 현재 범위가 아니다. 새 Sites 블로그에 게시한다. 사이트는 Sites의 기본 비공개로 먼저 배포한다. 누구나 접근하는 공개 전환은 사용자가 공개를 요청하면 현재 접근 설정과 지원 여부를 확인한 뒤 적용한다.

## 콘텐츠와 게시 절차

첫 버전에는 실제 원문 확인을 마친 소개 글 한 편을 넣어 목록과 본문을 검증한다. 주제를 별도로 지정하지 않으면 공식 홈페이지의 사업 영역을 소개하는 글을 선택한다. 기존 검토용 초안은 확인 없이 일괄 게시하지 않는다. 이는 구현자의 기본 제안이다.

후속 요청에서는 다음 절차로 처리한다.

1. 게시 목록과 사건 식별 기록을 읽어 중복 여부를 확인한다.
2. 사용자 지정 주제, 공식 보도자료 목록, 웹 검색 순서로 후보를 찾는다.
3. 기사나 공식 페이지 전체 본문을 확인한다. 제목이나 검색 요약만 확보되면 해당 후보는 보류한다.
4. 관련 기존 유라클 블로그 글을 실제로 읽고 용어와 문체를 참고한다.
5. 사실 중심 제목, 짧은 존댓말 문단, 핵심 강조, 2~3줄 요약, 출처를 작성한다. 기사 전문을 복제하지 않는다.
6. 숫자, 날짜, 주체, 제품명, 계획·진행·완료 구분을 원문과 재대조한다.
7. 본문과 목록을 함께 갱신하고 검증한 소스를 Sites에 배포한다.
8. 배포 성공을 확인하고 글 주소를 사용자에게 제공한다. 게시 성공이 불확실하면 먼저 기존 결과를 조회해 중복 게시를 피한다.

중복 사건은 같은 회사·발표·일자·제품을 기준으로 묶고, 출처 URL과 함께 기록한다. 적합한 소식이나 새로 설명할 내용이 없으면 중복 글로 채우지 않는다. 독립적인 추가 사실이 있으면 후속 글이나 기존 글의 갱신으로 다룬다.

## 범위와 성공 기준

현재 포함: 반응형 홈페이지, 대표 사진, 글별 페이지, 분류와 검색, 원고·출처 기록, 에이전트가 수행하는 요청형 게시, Sites 배포와 성공 확인.

현재 제외: 정기 예약, 뉴스레터, 댓글, 방문자 계정, 방문자 글쓰기, 결제, Drive의 사이트 내부 직접 연결, 기존 외부 블로그 계정 게시.

검증 항목:

- 실제 공식 사진과 로고가 깨지지 않고 읽기 쉬운 흰색 화면에 표시된다.
- 모바일과 데스크톱에서 가로 넘침 없이 제목·사진·본문을 읽을 수 있다.
- 검색·분류·글 링크·출처 링크가 작동한다.
- 게시한 글의 사실과 시점이 읽은 원문과 일치한다.
- 글 본문은 HTML로 직접 제공되어 페이지 주소를 새로 열어도 읽힌다.
- 배포된 사이트의 URL과 글 주소를 반환한다.
- 정기 작업을 생성하거나 예약 완료라고 설명하지 않는다.

## 구현자가 결정할 사항

사이트 이름은 “유라클 블로그”를 기본으로 한다. 사용 가능한 영문 URL, 콘텐츠 파일 형식, 작은 여백과 글자 크기, 접근성 속성, 정적 페이지 생성 방식은 구현자가 결정한다. 로고의 비율을 바꾸거나 사진을 회사 활동의 다른 사실로 설명하지 않는다. 사진을 가져올 수 없으면 이미지 처리 방식을 다시 정하고 실패를 감추지 않는다.

설계 확인 뒤 구현 계획을 작성하고 제작·검증·배포를 진행한다.
