## 1. 기사 선정 기준과 12건 검토

제목에 유라클이 있다는 이유만으로 수집하지 않고, 기사 전체 본문에서 유라클의 제품·사업·역할·고객·활동이 사건의 중심인지 검토했다. 통과한 사건 12건을 원문 링크, 직접 작성한 내용 요약, 선정 근거, 보도 시점의 진행 상태와 함께 저장했다. 선정 기사의 발행일은 2026-02-25부터 2026-11-03까지이며 전체 보도의 전수 목록은 아니다.

동일 발표의 다른 매체 보도는 중복 후보로 묶었다. 본문을 읽지 못한 기사 2건은 보류했고 개별 기사 본문이 없는 종목·시세 페이지는 제외했다. 회사 발표 수치는 발표 주체를 표시하고, 특정 제품 매출과 전체 회사 매출, 내부 실증과 일반 고객 효과, MOU·수주·개발 중·완료를 구분했다.

## 2. 목적과 게시물 형식 확정

목적은 적극적인 판매·구매 유도보다 유라클의 제품과 소식을 꾸준히 기록하고 이해하기 쉽게 설명하는 것이다. 기본 형식은 기사 화면 캡처가 아니라 근거를 확인한 텍스트 본문이며, 중요한 문장을 형광펜 적용 대상으로 지정하고 맨 아래에 짧은 요약을 둔다.

작성 순서는 제목 → 짧은 문단의 본문 → 본문 안 핵심 문장 강조 → 하단 핵심 요약 → 매체·발행일·원문 링크다. 차분한 존댓말을 사용하고 필요할 때 제품을 쉽게 설명한다. 채팅·Markdown의 굵은 표시는 형광펜 대상 지정이며 네이버 편집기에 실제 서식을 적용했다는 뜻은 아니다.

KT 협력 기사를 재구성한 샘플을 사용자가 승인해 스킬의 기준 예시로 저장했다. 현재 유라클 공식 블로그가 존재함을 확인했으며, 목록 첫 화면의 날짜만으로 운영 중단을 확정하지 않았다.

본문을 확인하지 못하면 보류하고, 추측으로 이름·수치·인용·성과를 만들지 않는다. 기존 작성 목록에 접근하지 못하면 중복 검사를 모두 완료했다고 주장하지 않는다. 승인 샘플은 형식 참고용이며 새 기사의 사실 근거를 대신하지 않는다.

외부 한국어 편집 지침은 번역투·반복·과장을 줄이고 의미·주체·수치·진행 상태를 보존하는 데 사용하도록 정했다. 마케팅 지침도 명료성·문체 일관성·근거 확인만 참고한다. 판매 유도나 감정 자극을 기본 목표로 삼지 않으며 외부 저장소·스킬을 별도로 설치하지 않았다.

## 4. 기존 블로그 표본 8편 수집

AI Insight·Mobile Insight·Use Case·Company에서 각 2편을 골라 원문 링크, 짧은 발췌, 요약, 문체·구성 관찰, 적용할 점과 그대로 옮기지 않을 점을 Google 문서로 정리했다. 블로그 자체 글 6편과 Company 목록에서 연결하는 외부 기사 2편을 구분했다.

개념 설명은 익숙한 상황과 비유, 활용 글은 산업·고객 상황, 고객 사례는 고객 과제와 유라클의 담당 범위, 회사 소식은 주체와 사건의 명확한 제시를 참고한다. 과거 기술 버전·요금·성능은 새 글의 현재 사실로 재사용하지 않는다. Use Case 목록은 접속 제한이 있어 검색으로 후보를 찾고 개별 본문을 확인했다.

여기서 ‘학습’은 자료를 읽어 작성할 때 참고하는 방식이다. 블로그 전체를 모델에 재학습시켰다는 의미는 아니다. 스킬에는 실제 읽은 관련 글과 참고한 특징을 게시물 밖 검토 메모로 남기도록 추가했다.

## 6. 자동화 범위와 남은 일

현재는 요청에 따라 기사 검토와 초안을 준비하는 단계다. 독립 HTML 사이트와 네이버 블로그 운영 방식을 논의했으나 최종 게시 경로는 확정하지 않았다. Playwright CLI는 네이버 편집 자동화의 후보로 검토했으며 설치하거나 실행 기능을 추가하지 않았다.

정기 실행·네이버 계정 생성·로그인·편집기 입력·형광펜 적용·임시저장·발행과 Sites 제작·배포는 아직 진행하지 않았다.

- [ ] 작성·수정한 초안을 사용자가 검토한다.
- [ ] 작성 이력과 사건별 중복 관리 방법을 정한다.
- [ ] 게시 플랫폼과 자동화 범위를 정한다.
- [ ] 필요 시 편집기에서 입력·서식·저장 동작을 실제로 확인한다.

## 7. Git 커밋 규칙과 이번 반영

이번 변경은 Conventional Commits의 `type(scope): description` 형식을 사용한다. 스킬 추가는 `feat(uracle-blog)`, 조사 기록과 초안 보관은 `docs(blog-agent)`로 나누고 각각의 본문에 변경 이유·범위·검증 내용을 적는다. `feat`는 작성 규칙을 추가했다는 의미이며 네이버 자동 게시 기능이 완성됐다는 뜻은 아니다.
