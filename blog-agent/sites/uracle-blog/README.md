# 유라클 블로그

Site ID: `appgprj_6ae9935f21c48191a39ef0fca6224e97`

기본 주소: https://uracle-journal-20261103.day1companyk-6083.chatgpt.site

이 주소는 배포 성공을 확인한 뒤 사용한다. 현재 접근 범위는 owner-private로 시작한다. 정기 작업은 설정하지 않는다.

## 파일

- `content/posts.json`: 원고, 분류, 게시일, 사건 식별자, 출처. 소개 글 1편과 저장 초안 기반 3편.
- `content/publications.json`: 초안 경로·사건·글 주소를 연결한 게시 기록. 원문 초안을 반복 게시하지 않기 위해 사용한다.
- `lib/site.mjs`: 원고 검증과 홈페이지·글 페이지 HTML.
- `lib/search.mjs`: 브라우저와 테스트가 함께 사용하는 검색 함수.
- `assets/`: 공식 회사 사진·로고와 스타일·브라우저 동작.
- `content/thumbnail-production-mono.json`: 현재 글별 썸네일 파일과 생성 문구·프롬프트. 주제별 흑백 사진에 검은색 반투명 레이어, 중앙의 흰색 큰 글자 3줄을 사용한다. 색이나 컬러 틴트를 넣지 않는다. 이전 시안의 생성 기록은 `thumbnail-production.json`에 보존한다.
- `scripts/build.mjs`: 검증한 원고를 글별 정적 HTML로 생성한다.
- `scripts/preview.mjs`: 로컬 미리보기 전용 서버.
- `.openai/hosting.json`: 같은 Site를 계속 사용하는 식별 정보.

## 작성과 게시

사용자가 이 사이트용 새 글을 요청하면 프로젝트의 `uracle-blog` 편집 기준으로 조사·작성·검토하고 게시한다. “초안만”, “게시하지 마”라는 요청은 우선한다. 주제와 원문을 확인하고 기존 `eventKey`와 출처를 조회해 중복 사건을 피한다.

### 채팅 명령: 글 게시

“글 게시”는 이 사이트에 실제로 게시하라는 명령이다. 현재 대화의 가장 최근 완성된 미게시 초안을 우선하고, 없으면 `drafts/`의 최신 미게시 초안을 선택한다. 기본 한 편을 게시하며 사용자가 여러 편을 지정하면 그 범위대로 처리한다. 출처 원문을 다시 확인하고 강조·요약·출처를 포함해 게시한 뒤 글 주소를 반환한다. 원고 경로·사건 식별자·게시 기록을 함께 대조해 같은 초안을 중복 게시하지 않는다. 미게시 초안이 없으면 그 사실을 알린다.

게시 기록과 원고가 로컬에 있어도 이전 배포가 실패했다면 게시 완료로 간주하지 않는다. 성공한 Sites 배포와 실제 포함된 버전을 확인하고, 대기 중인 배포가 있으면 먼저 완료 또는 실패 상태를 확인한다. 내부 검토 메모는 본문에 포함하지 않는다.

원고는 다음 항목을 갖는다: `slug`, `title`, `category`, `publishedAt`, `eventKey`, `excerpt`, `readMinutes`, `sections`, `summary`, `sources`. 분류는 회사 소식·AI·모바일 플랫폼이다. 소제목이 필요하면 `sections[].heading`, 핵심 강조는 `highlight`, 절별 출처는 `sourceIndex`에 sources 배열의 위치를 기록한다. summary는 최대 3개다. source에는 title, https URL, checkedAt을 기록하고 원문 발행일이 확인되는 기사는 publishedAt도 기록한다. 원문 게시일을 모르면 추측하지 않는다.

글별 `thumbnail`에는 `/assets/`의 전용 이미지 경로 `src`, 큰 글자 내용이 담긴 `alt`, 실제 `width`·`height`를 지정한다. 현재 썸네일은 1536×1024이며 목록과 본문에서 자르지 않고 전체를 표시한다. 홈페이지 상단 사진은 회사 사진을 사용한다. 기사 썸네일을 공식 사진이라고 표기하지 않는다.

1. 원문 본문과 관련 기존 유라클 블로그 글을 실제로 읽는다.
2. 원고를 `content/posts.json`에 추가하고 숫자·날짜·주체·진행 상태를 재대조한다.
3. `node --test`, `node scripts/build.mjs`를 실행한다. 검증에 실패하면 배포하지 않는다.
4. Sites 스킬을 읽고, 같은 Site의 상태와 접근 범위를 확인한다.
5. 필요한 경우 같은 Site의 소스 자격 증명을 갱신한다. 비밀값은 메모리에만 두고 source helper에 stdin으로 전달한다.
6. Sites source helper로 소스를 동기화·push하고 정확히 같은 소스로 만든 archive를 저장·배포한다. 새 Site를 만들지 않는다. 원격 소스가 앞서 있으면 먼저 정상적으로 열어 로컬 원고와 조정한다.
7. 배포가 terminal success인지 확인한 뒤 `/posts/<slug>/` 주소를 반환한다.

Sites 도우미 위치는 설치된 `sites` 플러그인의 SKILL.md에서 확인한다. Windows에서 Git의 폴더 소유자가 달라 연결이 실패하면 이 사이트의 절대 경로에 한정한 프로세스 단위 `safe.directory` 설정을 사용한다. 전역 wildcard 예외를 만들지 않는다. 소스 접근 토큰을 파일·프롬프트·출력에 기록하지 않는다.

## 검증과 현재 한계

최초 6개 동작 테스트 후 검토에서 발견한 두 문제를 실패 테스트로 재현하고 수정했다. 읽기 시간을 정수로 검증하며, 빌드마다 독립 임시 폴더를 사용해 이전 실패에서 남은 글이 다시 공개되지 않도록 했다. 전체 8개 테스트가 통과했다. 390px 화면에서 홈페이지·본문의 가로 넘침과 사진 로딩을 확인했고, 브라우저에서 검색의 빈 결과와 초기화를 확인했다.

사이트는 정적 콘텐츠다. 요청형 게시를 에이전트가 수행하며, 사이트 안에서 AI가 혼자 실행되는 서버나 예약은 없다. 정기 운영은 사용자가 다시 요청할 때 별도로 구현·검증한다. 사이트 내부의 Drive 연결은 현재 정책에서 허용되지 않아 추가하지 않았다.
