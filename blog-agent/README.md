## 현재 범위

대상 기업은 유라클이며, 투비소프트와 인스웨이브를 콘텐츠 구성의 참고 대상으로 조사했습니다. 기업별 제품의 성능이나 마케팅 성과를 비교한 프로젝트는 아닙니다.

`유라클 블로그 초안` 요청에 기사 확인 → 중복 검사 → 기존 블로그 참고 → 본문 작성 → 강조·요약·출처 → 문체 교정 → 사실 재대조 순서로 대응하도록 [.agents/skills/uracle-blog/SKILL.md](.agents/skills/uracle-blog/SKILL.md)에 규칙을 저장했습니다. 승인한 예시와 Drive 자료 위치도 함께 연결했습니다.

독립 블로그는 [사이트 작업 폴더](sites/uracle-blog/README.md)에 제작했습니다. [사이트 제작·배포 기록](docs/2026-11-03-site-progress.md)에서 배포 상태를 확인할 수 있습니다. 현재는 사용자가 요청할 때 에이전트가 글을 작성·검증하고 같은 Sites 블로그에 게시하는 방식입니다.

이 프로젝트 채팅에서 **“글 게시”**라고 보내면 가장 최근의 미게시 초안을 확인해 만든 블로그에 실제로 게시합니다. 특정 초안이나 여러 편을 지정할 수도 있습니다. 이미 게시한 원고는 중복해서 올리지 않으며, 미게시 초안이 없으면 그 사실을 알립니다.

정기 실행은 사용자의 최신 요청에 따라 설정하지 않습니다. 네이버 편집기 입력·형광펜 적용·임시저장·발행은 구현 범위에 포함하지 않습니다.

## GitHub 반영

이 프로젝트에서 **“커밋”**이라고 요청하면 마지막 GitHub 반영 이후의 변경과 진행 내용을 확인하고, `type(scope): description` 제목과 변경 이유·검증 설명을 붙여 `ShinHyerin/daejeon_01`의 `main` 브랜치 안 `blog-agent/`에 반영합니다. 다른 프로젝트에는 적용하지 않습니다. 세부 규칙은 [AGENTS.md](AGENTS.md)에 저장했습니다.

사이트 소스와 필요한 이미지는 함께 보관하고, Git 메타데이터·캐시·빌드 결과·배포 압축 파일·자격 증명은 제외합니다. GitHub 반영과 사이트 배포는 별도 작업입니다.

캡처 원본은 Google Drive에 보관하며 이 폴더에는 요약과 자료 링크를 기록합니다. Drive 파일은 기존 접근 권한이 적용됩니다.
