# 포트폴리오: 모바일던파 컨텐츠 시스템·던전 컨텐츠 기획 지원용

> "포트폴리오" = 이 파일. "과제"(업데이트 이력 기반 신규 기획 PDF)와는 다른 파일이다. 작업물은 `포트폴리오/` 폴더에만 저장한다.

## 작업 방식 (최우선)
- 사용자가 추가하라고 한 내용만 추가하고, 임의로 덧붙이지 않는다.
- 파일에 추가·수정하기 전에 반드시 사용자에게 확인받는다.
- 문서는 사용자와 문답하며 한 부분씩 점진적으로 작성한다 (질문 → 답변 → 초안 제안 → 확인 후 반영).

## 조건
- 주제·양식 **자유**, 제출 **필수**.
- 목적: 내가 **컨텐츠 시스템 및 던전 컨텐츠 기획** 직무에 맞는 사람임을 보여주는 것.

## 보여줘야 할 역량 (공고 + 인터뷰 기준)
- 던전/몬스터/보스 패턴, 컨텐츠 시스템, 밸런스를 기획해 본 경험
- '왜?'에 답하는 기획 논리 — 목표 경험 → 설계 → 근거
- 구현 가능한 명세 능력 (조건·수치·순서, 데이터/테이블)
- 던파 전투 액션 구조에 대한 이해
- 2D 연출 이해·경험 (우대)
- 장르·플랫폼을 가리지 않는 다양한 게임 경험과 분석 (우대)
- 문서·그림·발표 등 다양한 표현 방식
- 현상의 핵심을 파악해 정리하는 능력, 협업·커뮤니케이션 경험
- "최근 게임에서 불편했던 점 + 내가 기획자라면 어떻게 고칠지" 같은 관찰·개선 사고
- 직접 만들어 보고 수치를 바꿔 반복 검증한 경험 (프로토타입, 툴, 모드 등)

## 구성 가이드 (예시)
1. 표지 + 자기소개 (지원 직무 명시, 내 역량을 이 직무에 어떻게 쓸지)
2. 목차
3. 대표 작업 2~4개 — 각 작업마다:
   - 개요 / 기획 의도(목표 경험) / 문제 정의
   - 핵심 설계 (도식, 흐름도, 패턴 타임라인, 수치 테이블)
   - 나의 역할과 결과 / 배운 점
4. 게임 분석 (다양한 장르·플랫폼, 불편한 점과 개선안)
5. 기타 역량 (연출, 툴 제작, 데이터 분석 등)

## 원칙
- 직무와 관련 깊은 작업을 앞에 배치한다.
- 과제와 내용이 겹치지 않게 한다 (과제 기획을 포트폴리오에 복붙하지 않기).
- 각 작업은 결과물보다 **사고 과정과 근거**가 보이게 쓴다.
- 사실·수치·출처는 확인하고 남긴다.

## 출력
- 작업 파일과 최종본은 `포트폴리오/`에 저장.
