# 과제: 모바일던파 업데이트 이력 기반 신규 기획

> "과제" = 이 파일 하나. "포트폴리오"와는 다른 파일이다. 작업물은 `과제/` 폴더에만 저장한다.

## 작업 방식 (최우선)
- 사용자가 추가하라고 한 내용만 추가하고, 임의로 덧붙이지 않는다.
- 파일에 추가·수정하기 전에 반드시 사용자에게 확인받는다.
- 문서는 사용자와 문답하며 한 부분씩 점진적으로 작성한다 (질문 → 답변 → 초안 제안 → 확인 후 반영).

## 요구사항 (원문)
모바일던전앤파이터의 업데이트 이력을 바탕으로 **던전 컨텐츠, 컨텐츠 시스템, 캐릭터, 파밍 중 한 가지 주제**를 선택하여, **완결성 있는 신규 기획의 방향성 및 결론**을 도출하여 제출.
- 형식: **PDF** / 분량: **10장 이하** (표지 포함 여부를 고려해 10장을 절대 넘기지 않기)
- **과제 주제: 컨텐츠 시스템**

## 주제 선택 기준
- 지원 직무가 **컨텐츠 시스템 및 던전 컨텐츠 기획**이므로 주제는 **던전 컨텐츠** 또는 **컨텐츠 시스템**을 우선한다. (캐릭터·파밍을 고르면 직무 적합성 설명이 약해짐 — 사용자가 원하면 따르되 이 점을 알려줄 것)
- 필수 키워드 세 가지가 모두 보여야 한다:
  1. **업데이트 이력을 바탕으로** — 실제 업데이트 흐름을 근거로 문제/기회를 도출
  2. **신규 기획** — 기존 것의 단순 개선이 아니라 새 기획
  3. **완결성 + 방향성 + 결론** — 문제 → 방향 → 상세 → 검증 → 결론까지 닫힌 구조

## 작업 흐름
1. **업데이트 이력 조사** — 공식 공지/패치노트/업데이트 페이지에서 시즌·던전·레이드·시스템 업데이트를 시간순으로 정리. 출처(URL, 날짜) 기록. 확인 못 한 건 '추정' 표시. 정리본은 `과제/리서치/`에 저장.
2. **패턴 분석** — 이력에서 반복되는 흐름, 비어 있는 경험, 유저 니즈를 찾는다. "왜 이 시점에 이 업데이트를 했을까?"를 묻는다.
3. **문제 정의** — 근거(이력·유저 반응·플레이 경험)로 한 문장 문제 정의. 예: "여기서 유저가 이탈하니까 이게 필요하다" 형태의 논리.
4. **기획 의도 / 목표 경험** — 이 컨텐츠에서 유저가 어떤 경험을 하길 바라는지. **'액션 쾌감'과의 연결**을 명시.
5. **상세 기획** — 구현 가능한 언어로 쓴다.
   - 조건·수치·순서로 명세 ("체력 50% 이하 → 공격 속도 +X%, 패턴 순서 A→B→C에서 C→A→B")
   - 던전이면: 던전 구조/방 구성, 몬스터·보스 패턴(예고 시간, 판정 범위, 대응 방법), 입장 규칙, 플레이 시간
   - 시스템이면: 규칙, 흐름도, UI 흐름, 예외 처리
   - **모바일 특성 반영**: 터치 조작 기준 예고 시간·판정 범위, 짧은 세션(한 판 길이), 하루 컨텐츠 흐름
6. **다른 조각과 맞닿는 지점** — 보상/파밍, 캐릭터, 기존 컨텐츠(레거시)와 어떻게 맞물리는지, 공평함·편의 고려.
7. **검증·리스크** — 재미/안정성 검증 방법, 측정 지표, 예상 리스크와 대응, 라이브 서비스·고객 신뢰 관점.
8. **결론** — 방향성과 기대 효과를 한 장으로 닫는다.

## 권장 10장 구성 (예시, 상황에 맞게 조정)
1. 표지 + 한 줄 요약
2. 업데이트 이력 분석 (타임라인/표)
3. 발견한 문제·기회 (근거 포함)
4. 기획 방향성 & 목표 경험 (액션 쾌감 연결)
5~7. 상세 기획 (구조, 패턴/규칙, 모바일 최적화 — 도식·그림 적극 활용)
8. 기존 컨텐츠·보상·시스템과의 연계
9. 검증 계획·지표·리스크
10. 결론 및 기대 효과

## 제출 전 체크리스트
- [ ] 10장 이하 PDF인가
- [ ] 업데이트 이력이 실제 근거로 쓰였고 출처가 있는가
- [ ] 모든 기획 요소가 "왜?"에 답하는가 ("재밌을 것 같아서" 금지)
- [ ] 동료가 바로 구현할 수 있는 수준으로 조건·수치가 명세됐는가
- [ ] 모바일 환경(터치, 짧은 세션)을 반영했는가
- [ ] '액션 쾌감'과의 연결이 분명한가
- [ ] 문제 → 방향 → 상세 → 검증 → 결론으로 완결되는가
- [ ] 그림·도식으로 한눈에 전달되는가 (문서·그림 표현력도 평가 대상)
- [ ] 포트폴리오 내용과 섞이지 않았는가

## 출력
- 원본/작업 파일과 최종 PDF는 `과제/`에 저장.
- PDF 생성 후 페이지 수를 실제로 확인하고 보고한다.
