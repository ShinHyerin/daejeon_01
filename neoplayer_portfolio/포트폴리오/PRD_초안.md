# PRD 초안: 기획자의 커뮤니티 담당자

> 작성일: 2026-11-23 · 상태: 초안 (문답으로 계속 다듬는 중)
> 구조: 4MAT (Why → What → How → What if)

---

## 1. Why — 배경과 문제

흩어진 대량의 유저 의견을 다 읽을 수 없어서, 언제 무엇부터 고칠지 근거가 없다.

---

## 2. What — 컨셉

**기획자의 커뮤니티 담당자**
읽고 정리해서 개선 로드맵의 근거를 만든다.

---

## 3. How — 구현 방법

### 처리 단계
수집 → 정제 → 분류 → 집계 → 출력

### 멀티에이전트 구조

| 에이전트 | 하는 일 |
|---|---|
| 오케스트레이터 | 전체 순서를 관리하고 결과를 합침 |
| 수집 에이전트 | Aside로 커뮤니티와 업데이트 공지 수집 |
| 분류 에이전트 | 시스템 영역 8개로 분류하고 심각도 판단 |
| 검증 에이전트 | 분류 결과를 보지 않고 독립적으로 다시 분류한 뒤 비교 (독립 재분류형) |
| 요약 에이전트 | 영역별 부정 글에서 반복되는 문제를 한 문장으로 뽑고, 근거 글이 많은 순으로 TOP 5 정리 |
| 설문 에이전트 (발전 가능성) | 인게임 설문 서술형 정리 |

- 재검토 흐름: 검증 에이전트가 틀린 분류를 찾으면 오케스트레이터가 해당 글을 분류 에이전트에게 다시 보냄 (1회). 그래도 다르면 '담당자 검수'로 표시

### 분류 기준: 시스템 영역 8개
1. 재도전·실패 규칙
2. 횟수·주기·초기화
3. 모험단 구조
4. 동행(APC) 규칙
5. 재화·경매 규칙
6. 해금·단계 구조
7. 피로도 소모 방식
8. 컨텐츠 역할·엔드 컨텐츠

### 우선순위 기준
| 기준 | 판단 주체 |
|---|---|
| 빈도 | 에이전트 |
| 심각도 | 에이전트 |
| 개발 비용 | 사람 (기획자·개발팀) |
| 타이밍 | 사람 (기획자) |

### 최종 결과물
- Claude 아티팩트로 만든 사이트: Aside가 수집한 데이터를 정리하고 시각화해서 보여줌

| 보는 사람 | 결과물 |
|---|---|
| 기획팀 | 상세 표 |
| 개발팀 | 우선순위 표 |
| 리더 | 한 장 요약 |

### 추가 기능 ① 기본 결과 표시·결과 저장

- 목적: 에이전트는 링크로만 제출하므로, 링크를 연 사람이 실행하지 않고도 결과를 확인할 수 있게 한다 (니즈 4·5)
- 입력: 검증된 실행 결과를 아티팩트에 내장
  - 분류 결과: v0.3.1 실행분 140건 (검증/3차_분류결과.csv)
  - 반복 불만: v0.5 실행분 (검증/반복문제_v0.5.csv)
- 출력
  - 아티팩트를 열면 처리 완료 수, 분류 일치율, 반응 일치율, 검수 필요 건수, 주제별 게시글 수, 반복 불만 TOP 5, 게시글 목록을 바로 표시
  - 상단에 '기본 결과: v0.3.1 실행분(분류) · v0.5 실행분(반복 불만)' 표시
  - 결과 CSV 다운로드, TOP 5 CSV 다운로드 버튼 (기존 복사 버튼은 유지)
- 조건
  - [분류 시작]으로 직접 실행하면 새 결과로 바뀌고, [기본 결과 보기]로 되돌릴 수 있음
  - 직접 실행한 결과는 브라우저에 저장하지 않음 (보관은 CSV 다운로드로)
  - 내장 데이터에 커뮤니티 게시글 제목이 있으므로 공개 저장소에는 올리지 않음
- 확인 방법 (합격선)
  - 링크를 연 직후 분류 일치율이 포트폴리오 수치(87.4%)와 같음
  - 반복 불만 TOP 5가 v0.5 파일과 같음
  - 결과 CSV를 다운로드하면 140건이 모두 들어 있음

### 추가 기능 ② 업데이트별 보기

- 목적: 퍼소나의 핵심 업무인 '업데이트 후 유저 반응 보고서'에 바로 쓸 수 있게, 업데이트 단위로 반응을 본다 (고객 여정 1단계 "이번 업데이트, 유저들은 어떻게 느꼈을까?")
- 입력: CSV의 '관련 업데이트' 항목 (선택 항목, 비어 있으면 '업데이트 미지정')
- 출력
  - 업데이트 필터: [전체]와 업데이트별 선택
  - 업데이트를 고르면 KPI, 주제별 게시글 수, 게시글 목록이 그 업데이트 기준으로 바뀜
  - 업데이트 × 시스템 주제 표: 칸마다 게시글 수와 부정 건수
  - 반복 불만 TOP 5: 근거 게시글 중 선택한 업데이트 게시글이 있는 불만만 표시
- 조건
  - AI를 다시 호출하지 않고, 이미 분류된 결과로만 계산함
  - 업데이트 이름이 똑같아야 같은 업데이트로 묶임
- 확인 방법 (합격선)
  - 업데이트별 게시글 수의 합이 전체 게시글 수(140건)와 같음
  - 업데이트별 게시글 수가 Python 집계와 같음 (예: 9/17 신규 레이드 '루크' 27건)

### 추가 기능 ③ 보는 사람별 결과물

- 목적: 같은 분류 결과를 보는 사람에 따라 바로 쓸 수 있는 모양으로 꺼낸다 (최종 결과물 표의 기획팀·개발팀·리더, 고객 여정 '보고서 작성' 단계)
- 입력: 분류 결과와 반복 불만 TOP 5 (기본 결과 또는 직접 실행 결과, 업데이트 필터 적용)
- 출력: 결과 영역에 [기획팀] [개발팀] [리더] 탭
  - 기획팀 상세 표: 기존 게시글 목록 (제목·원문 링크·시스템 주제·검증 결과·심각도·반응·분류 근거)
  - 개발팀 우선순위 표: 시스템 주제마다 게시글 수, 부정 건수, 심각도 상·중·하 건수, 대표 불만 1개 — 게시글 수 순으로 정렬하고 심각도 '상' 건수는 열로만 표시
  - 리더 한 장 요약: 기간·게시글 수·출처, 최다 언급 주제, 반복 불만 TOP 3, 검수 필요 건수
  - 탭마다 [복사]와 [CSV 다운로드] (한 장 요약은 텍스트 복사)
- 조건
  - 에이전트는 빈도·심각도만 보여 주고, 개선 순서는 정하지 않음 (Non-goals 유지)
  - 심각도는 사람 정답과 비교하지 않은 값이므로 '참고값'으로 표시
  - 새 AI 호출 없이 기존 결과로만 만듦
- 확인 방법 (합격선)
  - 우선순위 표의 게시글 수 합이 주제별 게시글 수(시스템 주제 8개) 합과 같음
  - 한 장 요약의 수치가 화면 KPI·TOP 5와 같음
  - 세 결과물 모두 복사 또는 다운로드가 됨

### MVP 범위
- 데이터: 커뮤니티 데이터만 사용
- 정제(광고·도배·중복·무관한 글 제거): MVP에서는 Aside 수집 단계에서 무관한 글을 거름. 정제 에이전트는 발전 가능성
- 도구: Aside(수집), Claude 아티팩트 사이트(업로드·분류·검증·시각화), Python(일치율 계산 등 검증용)

## 4. What if — 기대 효과와 성공 지표

### 기대 효과
- 지금: 매번 2~3시간
- 이후: 매주 자동 실행하고 검토만

### 성공 지표 (합격선)

| 지표 | 합격선 |
|---|---|
| 분류 일치율 | 80% |
| 반복 문제 탐지 | TOP 5 중 4개 |
| 원문 링크 | 100% |

### 측정 결과 (최종 v0.3.1)

| 지표 | 합격선 | 결과 |
|---|---|---|
| 분류 일치율 | 80% | 기존 135개 87.4%, 신규 30개 86.7% → 달성 |
| 반복 문제 탐지 | TOP 5 중 4개 | 3/5 (v0.5, 미달) |
| 원문 링크 | 100% | 140개 모두 → 달성 |

- 반복 문제 탐지 판정 기준: 같은 레이드·규칙에 대한 불만이라도 유저가 겪는 불편이 다르면 다른 문제로 봄 (판정: 사용자)
- 미달 원인 1: 근거 글 수만으로 순위를 매겨, 찾아낸 문제(실패 시 횟수 차감)가 9위로 밀림
- 미달 원인 2: 관련 글이 다른 영역으로 분류돼 요약 대상에 들어가지 못함(여러 캐릭터 육성 부담)
- 개선(다음 버전): 순위 기준에 심각도 반영, 영역당 1개 제한 → 새 데이터로 검증

### 버전 기록
- 1차 79.3% → 2차 85.9% → v0.3.1 87.4% (신규 86.7%) → v0.4 91.9% (신규 83.3%, 기존 데이터에만 맞춘 개선이라 미채택)

### 발전 가능성
| 내용 | 연결 |
|---|---|
| 중국 커뮤니티 수집 + 중국 게임 은어·줄임말·고유명사 번역 | 니즈 2 |
| 정제 단계에서 비속어 처리 | 니즈 1 |
| 설문 에이전트로 인게임 설문 서술형 분류·정리 | 여정 지도 4단계 |
