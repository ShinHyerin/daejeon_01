# Persona × CJM 마스터 스킬

재료(입력 슬롯)만 바꾸면 어떤 산업에도 같은 순서로 돌아가는 기획 엔진이다.
순서: **0. 입력 슬롯 확인 → 1. 5-Whys 퍼소나 → 2. 6단계 CJM → 3. (호출 시) 모드별 HTML 기획서**

---

## 0. 입력 슬롯

작업 시작 시 아래 4개 슬롯을 채운다. 비어 있는 슬롯이 있으면 추측하지 말고 먼저 사용자에게 묻는다.

| 슬롯 | 의미 | 예시 형식 |
|---|---|---|
| **BRAND** | 브랜드/회사/IP 이름 | `{{BRAND}}` |
| **ITEM** | 팔거나 알릴 대상(제품·게임·콘텐츠·공간·상품) | `{{ITEM}}` |
| **TARGET** | 핵심 타겟 한 문장(누가 + 어떤 상태) | `{{TARGET}}` |
| **SITUATION** | 타겟이 ITEM을 떠올리는 구체적 순간(시간·장소·행동·채널) | `{{SITUATION}}` |

산업별 슬롯 채우기 예:
- 게임: ITEM=신규 모바일 RPG / SITUATION=출근길 지하철, 하던 게임이 질린 순간
- 뷰티 영상: ITEM=쿠션 파운데이션 튜토리얼 / SITUATION=오후 3시 화장 무너진 걸 화장실 거울로 본 순간
- 팝업/전시: ITEM=성수 팝업 / SITUATION=주말 오후, 갈 데 없어서 지도앱을 뒤지는 순간
- 여행·웰니스: ITEM=1박 2일 리트릿 / SITUATION=금요일 밤 퇴근 후 번아웃으로 연차를 고민하는 순간

## 1. 타겟 퍼소나 딥다이브 (5-Whys 결핍 분석)

**원칙**
- 나이·직업 같은 인구통계로 정의하지 않는다. SITUATION 속 **'진짜 짜증 나는 일상의 순간(Trigger)'** 하나에서 출발한다.
- Trigger는 장면처럼 쓴다: 시간 + 장소 + 하고 있던 행동 + 그 순간의 불편.
- Why를 5번 묻는다. 각 답은 **앞 답의 이유**여야 하며 한 단계씩 깊어진다.
  - Why 1~2: 행동·상황 차원 (무엇이 불편한가)
  - Why 3~4: 신념·두려움 차원 (왜 그게 신경 쓰이는가)
  - Why 5: **감정 + 바라는 자기 모습** (나는 어떤 사람이고 싶은가)
- 같은 말을 바꿔 반복하면 실패다. 각 Why마다 "그래서 그게 왜?"에 답이 되는지 점검한다.

**출력 형식**

```
### Trigger (짜증 나는 순간)
<장면 한두 문장>

| 단계 | 질문 | 답(결핍) |
|---|---|---|
| Why 1 | 왜 ~하는가? | ... |
| Why 2 | 왜 그게 문제인가? | ... |
| Why 3 | ... | ... |
| Why 4 | ... | ... |
| Why 5 | ... | <감정 + 바라는 자기 모습> |

### 한 줄 요약
> 이 사람은 ___ 하고 싶은데 ___ 때문에 못 한다.
```

추가로 짧게 정리: 핵심 결핍 키워드 3개 / 이 사람이 쓰는 말투(실제 속마음 어휘) / 이 사람이 가장 싫어하는 말(역효과 카피).

---

## 2. 6단계 고객여정지도(CJM)

퍼소나의 한 줄 요약과 Why 5(바라는 자기 모습)를 근거로 아래 6단계를 채운다.

`[1 문제 자각] → [2 릴스/검색 탐색] → [3 경쟁사 비교 & 의심(이탈 구간)] → [4 결정적 구매 트리거(간증/근거)] → [5 첫 사용/현장 경험] → [6 자발적 바이럴/재구매]`

**출력 형식 (표 1개)**

| 단계 | 고객의 속마음 대사 | 이탈하는 이유 | 누가 던지나 | 마케터·기획자가 던질 훅 카피 |
|---|---|---|---|---|
| 1 문제 자각 | "..." | ... | 공식/크리에이터/커뮤니티 | ... |
| 2 릴스/검색 탐색 | "..." | ... | ... | ... |
| 3 경쟁사 비교 & 의심 ⚠️ | "..." | ... | ... | ... |
| 4 결정적 구매 트리거 | "..." | ... | ... | ... |
| 5 첫 사용/현장 경험 | "..." | ... | ... | ... |
| 6 자발적 바이럴/재구매 | "..." | ... | ... | ... |

**작성 규칙**
- 속마음 대사는 따옴표 안의 1인칭 구어체. 퍼소나 말투를 그대로 쓴다.
- 이탈 이유는 "왜 여기서 창을 닫는가"를 구체 행동으로 쓴다.
- 훅 카피는 그 단계의 이탈 이유를 정면으로 막는 문장이어야 한다. 하나의 카피 = 하나의 이탈 이유.
- **누가 던지나** 열에는 그 훅을 실제로 전달하는 주체를 적는다: **공식**(브랜드 계정·공지·이벤트) / **크리에이터**(유튜버·인플루언서 등 정보 정리 콘텐츠) / **커뮤니티**(유저 인증·후기·커뮤니티 글). 한 단계에 주체가 둘 이상이면 함께 적고 각각의 훅을 나눠 쓴다.
- 공식 카피는 이벤트·공지처럼 **사실(혜택·기간·조건)을 전하는 형태**로 쓰고, 감성만 있는 문구("기다리던 ~이 왔어요" 류)는 쓰지 않는다. 공략·정보 정리형 제목("~ 전에 챙길 것 3가지", "~ 총정리")은 크리에이터 몫으로 나눈다.
- 3단계는 가장 이탈이 큰 구간으로 표시(⚠️)하고, 4단계 트리거는 **증거 유형**(성분표, 실사용 후기, 비교 실험, 전문가 코멘트 등)을 명시하되 내용은 실데이터 슬롯으로 둔다.
- 표 아래에 "가장 먼저 고칠 단계 1곳 + 이유" 한 줄을 붙인다.
- 산업이 오프라인/여행이면 단계명을 바꾸지 말고 내용만 맞춘다(예: 5단계 = 현장 입장·체험, 6단계 = 인증샷·재방문·지인 추천).

## 3. 산업별 출력 스위치 (모드)

사용자가 "모드 A/B/C"를 부르면, **반드시 위 1·2의 퍼소나와 CJM을 근거로** 해당 기획서를 HTML 웹페이지 한 장으로 만든다. 퍼소나·CJM이 아직 없으면 먼저 1·2를 수행한다.

모든 모드 공통 섹션:
1. 입력 슬롯 요약 (BRAND / ITEM / TARGET / SITUATION)
2. 퍼소나 한 줄 요약 + Why 5
3. 이 기획이 공략하는 CJM 단계(번호)와 그 단계의 이탈 이유
4. 모드별 본문 (아래)
5. 실데이터 체크리스트: 문서 안의 모든 `[실데이터 입력]` 항목을 모아 표로 정리
6. 성공 지표(KPI 항목명만, 목표 수치는 `[실데이터 입력]`)

### 모드 A — 15초 릴스/숏폼 영상 에이전트
- 0~3초 훅(첫 자막 + 첫 화면) 시안 3개, 각 시안이 노리는 CJM 단계 표기
- 15초 콘티 표: 구간(0–3 / 3–7 / 7–12 / 12–15초) × 화면 / 자막 / 오디오·사운드 / 노리는 감정
- 캡션 본문 + 해시태그 방향 + CTA 1개
- 댓글 예상 반응과 고정 댓글 시안
- 촬영 체크리스트(소품·장소·출연자 유형)

### 모드 B — 오프라인 팝업/전시 공간 기획 에이전트
- 공간 콘셉트 한 줄 + 퍼소나 결핍과의 연결
- 동선 표: 입구 → 존 1~N → 포토존 → 구매/출구, 각 존의 체험·감정·대응 CJM 단계
- 대기열·체류 경험 설계(대기 중 콘텐츠, 이탈 방지 장치)
- 인증샷·UGC 장치와 현장 문구(사이니지 카피)
- 운영 체크리스트(인력·소요 시간·리스크). 위치·면적·예산·운영 기간은 `[실데이터 입력]`

### 모드 C — 여행사 테마 투어 기획 에이전트
- 상품명 후보 3개 + 상품 한 줄 콘셉트
- 일정표: Day/시간대 × 프로그램 × 퍼소나 결핍 해소 포인트 × 대응 CJM 단계
- 예약 전 의심 해소 장치(포함/불포함, 취소 규정, 안전·건강 안내 항목)
- 여행 후 바이럴·재구매 장치(후기 미션, 재방문 혜택 구조)
- 가격·숙소·이동 수단·제휴처·최소 출발 인원은 `[실데이터 입력]`

### HTML 출력 규칙
- 단일 HTML 파일(CSS 인라인, 외부 이미지 없음), 한국어, 모바일에서도 읽히는 반응형.
- 색상·폰트·테마 등 디자인 세부는 사용자가 정하지 않았다면 **임의로 정하지 말고 먼저 묻는다**. 답이 없으면 무채색 기본 스타일로 만들고 그 사실을 알린다.
- 파일 저장 위치와 파일명은 생성 전에 사용자에게 확인한다. 기본 제안: `outputs/<BRAND>_mode-<A|B|C>.html`
- `[실데이터 입력]` 항목은 화면에서 눈에 띄게(배지·밑줄 등) 표시한다.

## 4. 규칙 (반드시 지킬 것)

1. **지어내지 않는다.** 제품 스펙, 성분, 칼로리·당류 등 수치, 가격, 판매량, 순위, 후기·별점, 인플루언서 이름, 수상 이력, 매장 위치, 경쟁사 실제 정보는 사용자가 제공했거나 확인된 출처가 있을 때만 쓴다. 모르면 `[실데이터 입력]`으로 남긴다.
   - 예: "1개당 `[실데이터 입력: 칼로리]`kcal", "구매자 후기 `[실데이터 입력: 실제 리뷰 원문]`"
2. 후기·간증은 **형식(어떤 유형의 증거가 필요한지)**만 설계하고 문장 자체를 실제 후기처럼 꾸며 쓰지 않는다. 예시 문장이 필요하면 `(예시 문안)`이라고 표시한다.
3. 경쟁사는 실명 대신 "경쟁 제품 A(일반 아이스크림)"처럼 유형으로 쓰고, 실명 비교가 필요하면 `[실데이터 입력]`.
4. 건강·다이어트·웰니스 관련 효능 표현은 과장하지 않는다("살 안 찌는", "치료" 등 단정 금지). 표시·광고 규정 검토가 필요하면 그 사실을 적는다.
5. 퍼소나와 CJM에서 근거가 없는 기획 요소는 넣지 않는다. 모든 훅·존·프로그램은 대응하는 Why 또는 CJM 단계를 표기한다.
6. 출력은 한국어로 한다.
